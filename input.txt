@c buddy slots. In practice, it is likely that more than one block of memory
will be used for allocating small segments of memory, and therefore more
than one instance of a buddy allocator will be required.
A single block of memory can be used to house the metadata of multiple
instances of a buddy allocator. One instance takes up 10 words of space
without any padding (AVAIL is 7 words, TAGS is 2 words, the address of BLOCK is 1 word).
A maximum of 6 instances can fit on a block.
Each memory region associated with a potential instance will be referred
to as a "slot". 4 words are a left over. These will be used to construct
a TOP struct that can be passed into calls to the buddy memory allocator.
A slot is selected, and then the addresses of AVAIL, BLOCK, and TAGS will
be set in the TOP struct before the buddy memory allocator is called.

@c param stack pop. this test will verify pop behavior in a similar way that
push was tested.
@c initialize RC/stack.
@m #0 go ri pi
@c set up blocks.
@m #40 ra #41 ra #42 ra
@c push some blocks onto the stack. print the counts: (2 2 2).
@m #40.0 pu #41.0 pu #42.0 pu #40.1 rxsppw #41.1 rxsppw #42.1 rxsppw
@c pop once. print the counts: (2 2 1).
@m po #40.1 rxsppw #41.1 rxsppw #42.1 rxsppw
@c pop twice. print the counts: (1 1 1).
@m po po #40.1 rxsppw #41.1 rxsppw #42.1 rxsppw
@c attempt to pop again. print the error code (1)
@m po sppe ce
@p
@l test_pstack_hold:
@c param stack hold. the 'hold' operation performs hold/unhold on the
last item pushed onto the stack.
@c set up RC/stack. add blocks.
@m #go ri pi #40 ra #41 ra #42 ra
@c hold on an empty stack. error code should be 1.
@m #0 ph sppece
@c push three blocks onto the stack and print their hold flags: 0 0 0
@m #40.0 pu #41.0 pu #42.0 pu #40.2 rxsppw #41.2 rxsppw #42.2 rxsppw
@c hold pop: 0 0 1
@m #0 ph po #40.2 rxsppw #41.2 rxsppw #42.2 rxsppw
@c hold pop hold pop: 1 1 1
@m #0 phpo #0 phpo #40.2 rxsppw #41.2 rxsppw #42.2 rxsppw
@c push unhold push unhold: 0 1 0
@m #40.0 pu #1 ph #42.0 pu #1 ph #40.2 rxsppw #41.2 rxsppw #42.2 rxsppw
@p
@l test_pstack_rot:
@c parameter stack rotate. A standard forth stack rotation operation.
@c The stack transitions $[a b c] \to [c a b]$.
@c Set up blocks, stack.
@m #0 go ri pi #40 ra #41 ra #42 ra
@c Push {\tt 0x40}, {\tt 0x41}, {\tt 0x42}, pop and print: 42 41 40.
@m #40.0 pu #41.0 pu #42.0 pu po0pxsppw po0pxsppw po0pxsppw
@c push the blocks again. rotate. pop and print: 41 40 42.
@m #40.0 pu #41.0 pu #42.0 pu pR po0pxsppw po0pxsppw po0pxsppw
@p
@l test_pstack_dup:
@c pstack duplicate. dup operation. Stack goes $[a b] \to [a b b]$.
@c set up stack with 2 blocks.
@m #0 go ri pi #40 ra #41 ra
@c push 2 blocks onto the stack, and duplicate. print results: 41 41 40.
@m #40.0 pu #41.0 pu pd po0pxsppw po0pxsppw po0pxsppw
@p
@l test_pstack_swap:
@c pstack swap. swaps the last two items on the stack.
The stack state goes from $[a, b] \to [b, a]$.
@c initialize the stack, add some blocks.
@m #0 go ri pi #40 ra #41 ra
@c push blocks, pop and print: 41 40
@m #40.0 pu #41.0 pu po0pxsppw po0pxsppw
@c push blocks again. swap. pop and print: 40 41
@m #40.0 pu #41.0 pu ps po0pxsppw po0pxsppw
@p
