@c for granular allocations smaller than a block,
a buddy system allocator is utilized.
This allocator was adopted from the algorithm
descriped in Knuth's TAOCP volume 1, chapter 2.5.
The following test was adapted from the prototype
developed separately.
@c blocks 0, 1, and 2 will be used.

@l test_mem_init:
@c initialize a stack at block address 0
@m #0bw ai
@c the memory allocator needs 4 segments of memory
TOP is a 4-word segment containing the addresses
of the other memory segments, and is what is passed
around when allocating memory.
BLOCK is the block of memory used for allocation.
AVAIL is a 8 word segment containing the block
lists of various $2^k$ sizes in the buddy system
algorithm.
TAGS is a 2-word segment used to indicate if
a particular sub-block of memory is being used.
These memory addresses will be fixed. Using block
address notation block.word, they will be the
following:
TOP=B1.0=#100.
BLOCK=B2.0=#200.
AVAIL=B1.4=#104.
TAGS=B1.12=#10C.
@c push TOP, BLOCK, AVAIL, TAGS onto the stack,
and then call the memory initializer.
@m #0 gb #100bwaa #200bwaa #104bwaa #10Cbwaa mi
@c print an initial checksum of the initialized memory allocator
@m #100bw mc sppw
@p
